# Decisions

Append-only log, newest entry at the bottom, one line per entry in the format "- YYYY-MM-DD: <decision in one line>. See <file>."

- 2026-09-30: Split is image-level, ~70/15/15, Fine24-stratified (Sechidis-style greedy iterative), shared by both variants; cross-split session leakage accepted and reported. See data/README.md.
- 2026-09-30: EoMT scale jitter is `scale_range: [0.5, 1.5]` (like YOLO's `scale: 0.5`) instead of upstream's COCO LSJ 0.1–2.0. See docs/eomt.md.
- 2026-10-01: Added native-resolution random-crop training experiments (`crop-640`/`crop-1024`, `eomt-crop-640`/`eomt-crop-1024`). See docs/experiments.md.
- 2026-10-01: YOLO crop experiments use `cache: false` (a native RAM cache is ~34 GB per GPU process). See docs/experiments.md.
- 2026-10-01: YOLO crop experiments use `workers: 4` / `6` after 12 workers ran out of RAM under DDP. See docs/experiments.md.
- 2026-10-01: EoMT crop experiments follow Mask2Former's instance recipe exactly; YOLO keeps Ultralytics' defaults. See docs/experiments.md.
- 2026-10-02: Fixed the DDP EoMT evaluation hang (non-zero ranks exit after `fit`, rank 0 destroys the process group). See docs/eomt.md.
- 2026-10-03: EoMT training applies the transforms to polygon points and rasterises only the instances in the crop (`PolygonTransforms`). See docs/eomt.md.
- 2026-10-03: EoMT validation scores only the final block. See docs/eomt.md.
- 2026-10-03: All four EoMT experiments validate every 5 epochs (`trainer.check_val_every_n_epoch: 5`). See docs/experiments.md.
- 2026-10-03: Measured per-sample data loading with `PolygonTransforms` (e.g. eomt-crop-640 ~91 ms vs. 336 ms on the dense-mask path). See docs/experiments.md.
- 2026-10-06: EoMT uses upstream's code directly: training via its LightningCLI command line, upstream's `Dataset`/`Transforms`/`MaskClassificationInstance` (dropped `PolygonTransforms`, `GpuMapInstance`, `AnyResEoMT` and the `eomt-crop-*` experiments); `batch_size` is per GPU. See docs/eomt.md.
- 2026-10-06: No training/evaluation code of ours: `src/train.py`, `src/evaluate.py` and the YOLO/EoMT trainer and evaluator classes are removed. Training and evaluation are the frameworks' own entry points (`yolo segment train cfg=...`, `YOLO(best.pt).val()`, upstream EoMT's `fit`/`validate`), built per cell by `src/experiments.py`; EoMT's prediction export and latency come from a Lightning callback (`CocoPredictionWriter`) plus a noted `eval_step` edit. YOLO is vanilla: the native-crop trainer (and `crop-640`/`crop-1024`), our W&B naming and DDP AutoBatch are gone. EoMT's native metric is upstream's torchmetrics (faster_coco_eval backend), which makes its test pass ~2.4 s/image (model ~65 ms); `src/eomt/metrics.py` and the per-class framework CSVs are dropped. See docs/eomt.md, docs/yolo.md, docs/evaluation.md.
- 2026-10-06: Scope narrowed to CropOrWeed2. Fine24 is dropped (code, data, checkpoints and results deleted), and the split is re-stratified on CropOrWeed2's per-class instance counts, superseding the 2026-09-30 Fine24 stratification. All earlier runs (`output/experiments/`, `output/eval/`, `results/experiments/`) were from the old split and were deleted. The data layout is flat, `data/seed<N>/{images,labels,annotations}/`. See data/README.md.
- 2026-10-06: Vegetation ignore regions are COCO `iscrowd=1` annotations (one per category) in a per-split COCO ground truth written by the converter (`annotations/<split>.json`, crowd in val/test only). They replace the `ignore/` sidecar and `src/seg_dataset.py`. EoMT's dataset reads the json via upstream's own loop, its torchmetrics val mAP honours the crowd regions, and `src/cropandweed_eval.py` is plain hotcoco COCOeval with the paper's area ranges. The plain `coco` reference protocol is dropped. See docs/evaluation.md.
- 2026-10-07: The downsampling regimes are rectangles, 1024x592 and 1280x736 (`yolo-*`, `eomt-*`; YOLO cells renamed from `ft-`), replacing the square 640/1280 boxes; YOLO trains at square `imgsz` 1024/1280 with mosaic (same downscale; `rect=True` would drop mosaic and shuffling). Added `eomt-native-1280` (EoMT only): native 1280 crops, scale jitter [0.75, 1.5] of native, tiled eval with 640 px (50%) overlap from the 99th-percentile object size, via an `eval_tile_overlap` edit of `mask_classification_instance.py`; test eval stays upstream's instance top-k, not the notebook's panoptic per-pixel inference. See docs/experiments.md.
- 2026-10-07: `eomt-native-1280` became `eomt-native-1024`: random 1024 crops at native scale (no scale jitter, `scale_range: null`), instances < 25% inside the crop dropped (`min_visible_fraction`), crops without instances redrawn (upstream); in-training val on a fixed 2x2 grid of 1024 tiles (`TiledDataset`) with instances < 25% inside a tile as `is_crowd`; the test eval stays full-frame (4x2 merged native tiles, >= 640 px overlap). EoMT's val mAP is computed on the final layer only; top-k stays upstream's 100 in val (300 in the test eval); a `PredictionPlotter` callback logs pred vs. GT of the 2 val frames with the most plants to W&B. Measured epoch times: EoMT validation (~9-17 min per pass, CPU mask encoding in torchmetrics) is 40-55% of an EoMT run. See docs/experiments.md, docs/eomt.md.
- 2026-10-07: EoMT validation speed-ups: the val mAP on masks downscaled by half (`metric_mask_scale: 0.5`; test eval native), upstream's PIL resize replaced by a GPU antialiased `interpolate`, and `val_batch_size` (val 32/16/32 tiles, test 16/16/4 frames per GPU; YOLO test batch 64) while training stays at 8 per GPU; `num_workers` stays 8 (the loader isn't the bottleneck). A val batch of 8 went from 8.2 s to 3.1 s; `latency_ms` is now per-image time at the eval batch, single-image latency to be measured separately. See docs/eomt.md, docs/experiments.md.
- 2026-10-07: The test eval's torchmetrics framework metric also uses half-scale masks (`metric_mask_scale: 0.5` everywhere; the previous entry's native test metric is reverted): ~0.8 s instead of 2.6 s per frame. The CropAndWeed-protocol score (hotcoco on the native `predictions.json`) stays native. See docs/eomt.md.
- 2026-10-07: EoMT's mask mAP is our `src/eomt/mask_ap.py:MaskAP` instead of torchmetrics' `MeanAveragePrecision` (whose per-mask CPU copy + RLE encoding in a Python `update` loop was the val bottleneck; faster_coco_eval is multithreaded only in `compute()`). As Ultralytics' validator, mask IoU is a GPU matmul; matching and accumulation follow pycocotools/hotcoco under the CropAndWeed protocol (crowd ignore, 16^2 bbox-area minimum, bbox-area buckets), so `val_ap_all` (best.ckpt) tracks the reported metric; it reproduces `cropandweed_eval.evaluate` exactly on synthetic data and on smoke test evals. Masks are scored at native resolution again (`metric_mask_scale: 1.0`; downscaling stays available, with the area ranges scaled). Val ~0.13 s/frame (was ~0.4 at half scale), test eval 0.19 s/frame (was 0.8); ~13 h per seed. See docs/eomt.md, docs/experiments.md.
